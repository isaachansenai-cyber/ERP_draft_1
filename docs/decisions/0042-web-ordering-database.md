# 0042 Website ordering in the database (W2)

Operator request (session, 2026-11-26): build W2 of the website plan. Migration `0027_web_ordering.sql`. Choices not settled by ADR 0040:

- **Staff-only reference reads.** Ten tables (locations, units, reason codes, items, unit conversions, recipe versions and components, app settings, setup gates, return policy) had RLS policies `using (true)` for any signed-in session. Website visitors are signed-in (anonymous) sessions, so those policies now require an active employee (`private.is_staff()`). A pgTAP probe calls every function a signed-in session can execute, with null arguments, as an anonymous visitor, and fails if anything other than the web functions and three harmless public reads answers.
- **Auth sign-ups are on.** Supabase Auth refuses anonymous sign-ins while sign-ups are disabled. `supabase/config.toml` now enables both, which also lets anyone register an e-mail account. Such an account has no employee record, so it reaches exactly what an anonymous visitor reaches (the probe above). Captcha and sign-up rate limits for the hosted projects are set in the dashboard in W5. **Owner decision pending** for the hosted projects.
- **Idempotency actor for visitors** is `web:<auth uid>` in the existing `private.request_log`, so a visitor's retries replay and one visitor cannot read another's results (`web_get_request_result`).
- **One acceptance path.** `private.accept_order_core` holds the order insert, line/price/tax snapshot, all-or-nothing reservation, state event and audit. `accept_order` (POS) and `web_place_order` both call it after their own checks; the shared gates live in `private.require_order_gates`. The POS behavior and its tests are unchanged.
- **System actor `EMP-WEB`** ("Online ordering") accepts web orders and records demo simulated tenders. Constraints stop it from ever getting a login or a role; the demo reset recreates it, and the demo-mode switch does not count it as staff.
- **Contact details** live in their own append-only table `web_order_contacts`, readable only by managers of the order's location and the owner. Employees see the pickup name on the order, as for POS orders.
- **Slot rule** (`private.web_pickup_slots`, clock passed in for tests): the kitchen starts at opening time, and the slowest item's lead days and cook minutes decide the earliest slot. Slot capacity is enforced by locking the location's web settings row during placement.
- **Open-order limit** of 3 per visitor, phone and e-mail. The planned attempts-per-hour counter was dropped: a refused attempt rolls back its own count. Auth rate limits cover repeated attempts.
- **Demo values** for hours, capacity, cook minutes and website text are in `data/demo/web_demo_seed.json` (loaded by `import-demo-seed.ts`), not in the delivered `demo_seed.json`. Allergen drafts stay unreviewed, so the website does not publish them.

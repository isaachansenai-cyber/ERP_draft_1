# 0042 Website ordering in the database (W2)

Operator request (session, 2026-11-26): build W2 of the website plan. Migration `0027_web_ordering.sql`. Choices not settled by ADR 0040:

- **Visitors do not sign in** (owner decision, 2026-11-26). The site uses the public anon key. `anon` may execute only `get_public_app_mode` and the six `web_*` functions, and reads no table. Supabase Auth sign-ups and anonymous sign-ins stay **off**, as before. A first W2 draft used anonymous sign-in; it was dropped because Auth only allows it with public sign-ups switched on.
- **Staff-only reference reads (defense in depth).** Ten tables (locations, units, reason codes, items, unit conversions, recipe versions and components, app settings, setup gates, return policy) had RLS policies `using (true)` for any signed-in session. They now require an active employee (`private.is_staff()`), so an Auth account without one (for example deactivated staff) reads nothing. pgTAP probes call every public function, with null arguments, as `anon` and as such an account, and fail if anything other than the expected public reads answers.
- **Idempotency actor for visitors** is the constant `web` in the existing `private.request_log`. The request key is a random UUID generated by the browser, so a retry replays and only the sender can look up its result (`web_get_request_result`).
- **One acceptance path.** `private.accept_order_core` holds the order insert, line/price/tax snapshot, all-or-nothing reservation, state event and audit. `accept_order` (POS) and `web_place_order` both call it after their own checks; the shared gates live in `private.require_order_gates`. The POS behavior and its tests are unchanged.
- **System actor `EMP-WEB`** ("Online ordering") accepts web orders and records demo simulated tenders. Constraints stop it from ever getting a login or a role; the demo reset recreates it, and the demo-mode switch does not count it as staff.
- **Contact details** live in their own append-only table `web_order_contacts`, readable only by managers of the order's location and the owner. Employees see the pickup name on the order, as for POS orders.
- **Slot rule** (`private.web_pickup_slots`, clock passed in for tests): the kitchen starts at opening time, and the slowest item's lead days and cook minutes decide the earliest slot. Slot capacity is enforced by locking the location's web settings row during placement.
- **Open-order limit** of 3 per phone number and per e-mail. With no sign-in there is no per-visitor identity, and an attempts-per-hour counter would roll back with a refused attempt. Accepted risk until W5: someone could place bogus orders under several made-up contacts, which reserve stock until staff cancel them; slot capacity (4 per 15 minutes) bounds it.
- **Demo values** for hours, capacity, cook minutes and website text are in `data/demo/web_demo_seed.json` (loaded by `import-demo-seed.ts`), not in the delivered `demo_seed.json`. Allergen drafts stay unreviewed, so the website does not publish them.

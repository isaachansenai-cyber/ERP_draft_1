# 0044 Website checkout, receipt and staff side (W4)

Operator request (session, 2026-11-26): build W4. Choices not settled by ADRs 0040–0043:

- **Exact total before placing.** `web_get_menu` also returns the location's current tax rate as exact text (migration 0028). Checkout shows subtotal, tax and total with the ERP's rule (tax rounded half up per line, decimal.js); the ERP still computes and snapshots the real total, and the receipt shows the ERP's numbers. A test checks the two agree ($41.80).
- **Safe placement without sign-in.** One request key per location's checkout, kept in `sessionStorage` until an order is placed. A definite refusal (`P0001`) is reported at once. When no answer arrives, or the answer cannot be read, the site asks `web_get_request_result` with the same key before saying anything: committed → the receipt; not found → "not placed, you can safely try again"; unknown → "please do not order again yet" with a Check again button. Tests cover a request that never reaches the ERP and one whose answer is lost after the ERP committed it.
- **Payment wording** comes from the server's data mode (`get_public_app_mode`): "Simulated payment (demo)" or "Pay at pickup". No card fields.
- **Receipt** at `#/order/<token>`, refreshed every 30 s, printable (navigation and footer hidden in print). It shows the pickup code, time in Mountain Time, lines, tax, total and payment, never contact details.
- **Kitchen.** Web orders carry a "Web order" badge, the pickup time and a start-by time (pickup minus the longest cook time); dishes with lead days are flagged "Needs prep the day before". Orders for a later day sit in a "Scheduled for later days" lane, and queues sort by pickup time. Display only (`src/lib/webOrders.ts`).
- **Settings → Website** (owner; managers see it read-only): per-location ordering switch and limits, weekly opening hours, cook minutes per dish, and website text with an allergen note that is published only when the owner ticks that it was checked against product labels. `set_web_menu_content` treats blank text as "none" (0028). Forms are keyed by location or item, so a save never remounts them and wipes the confirmation.
